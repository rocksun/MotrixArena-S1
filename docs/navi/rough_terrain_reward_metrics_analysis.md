# `vbot_navigation_section01` 崎岖地形奖励指标分析

## 1. 分析范围与结论

本文针对 [`8factors.md`](./8factors.md)“奖励目标”中与复杂地形通过能力有关的奖励项，结合当前实现
`VBotSection01Env._compute_reward()` 和 `VBotSection01EnvCfg.RewardConfig`，说明每个指标的计算方式、行为含义、相互作用和实现风险。

这里的“崎岖地形”按整条越障路线理解，包括：

1. 崎岖高度场；
2. 崎岖区出口的落差；
3. 落差之后的上坡及坡顶衔接。

当前奖励设计的总体意图很明确：先用通用步态奖励让四条腿持续交替迈步，再在不同路段追加抬脚、落差跟腿、坡上驱动和姿态约束。但代码中有几项指标不能完全表达注释中的意图：

- `per_leg_swing`、`drop_leg_catchup`、`slope_leg_drive` 取“四条腿当前腾空时间的最小值”。正常行走时总有腿着地，其腾空时间为 0，因此这些奖励在正常步态中通常为 0，主要只在四足同时腾空时非零。
- `slope_front_drive` 取两条前腿当前腾空时间的最小值，只有两条前腿同时离地时才非零，并不能稳定衡量前腿是否轮流积极迈步。
- `swing_foot_height` 在没有任何摆动腿时误差为 0，因而得到最大原始奖励 1；四足持续着地并不会被该指标本身排斥。
- `drop_leg_catchup` 和 `slope_leg_drive` 的名字、注释强调后腿，但公式没有单独选择后腿。
- `gait_symmetry` 只检查对角腿接触状态是否一致；四足全部着地同样得到满分，不能单独证明形成了对角步态。

因此，这些指标目前更准确的理解是“带有区域门控的足端状态塑形项”，不能直接等同于“成功抬脚”“后腿已跟上”或“形成了稳定对角步态”。

## 3. 公共变量和生效区域

### 3.1 公共变量

设：

- `c_i`：第 `i` 条腿是否接触地面，接触为 1，腾空为 0；腿顺序为 `FR、FL、RR、RL`；
- `t_i`：第 `i` 条腿当前连续腾空时间。每个 0.01 s 控制步增加 0.01 s，触地后重置为 0；
- `T = 0.55 s`：配置中的腾空时间目标；
- `m = I(||command_xy|| > 0.05)`：是否存在有效平移命令；
- `g_x`：单位重力向量旋转到机身坐标系后在机身 X 轴上的分量，用作俯仰代理量；
- `y`：机身中心在世界坐标系中的 Y 坐标。

`active_move` 只取决于命令速度，不取决于机器人是否真的移动。因此机器人即使原地不动，只要控制器仍在下发移动命令，带 `active_move` 的奖励仍处于开启状态；是否真的移动主要由 `anti_stall`、速度跟踪和进展奖励约束。

### 3.2 区域门控

| 区域 | 代码范围 | 生效项 |
| --- | --- | --- |
| 崎岖区扩展范围 | `-1.65 <= y <= 1.85` | `swing_foot_height` |
| 出口落差区 | `1.3 < y <= 1.8` | `drop_leg_catchup`、`drop_pitch` |
| 坡道驱动区 | `1.8 <= y < 6.9` | `slope_leg_drive`、`slope_front_drive` |
| 坡道姿态区 | `2.0 <= y < 6.9` | `slope_pitch`、`slope_hip` |

这和 `8factors.md` 对物理地形的概括范围并不完全相同。物理崎岖高度场约为 `-1.5 < y < 1.5`，但抬腿奖励使用了更宽的 `[-1.65, 1.85]`，以覆盖进入和离开地形时的过渡。`1.3–1.8 m` 内抬腿奖励和落差奖励同时生效；`1.8–1.85 m` 内抬腿奖励和坡道驱动奖励同时生效。

区域边界使用机身中心位置，而不是单只脚的位置。因此机身进入某区域时，前后脚可能仍分别位于边界两侧；这种提前或延后的塑形是设计上的近似。

## 4. 通用步态指标

这些指标不只在崎岖区生效，但它们构成了复杂地形专项奖励的基础。

### 4.1 `feet_air_time`：落脚时结算的腾空时长

公式可写为：

```text
r_air = m × Σ_i [(t_i_before_contact - T) × first_contact_i]
R_air = 1.0 × r_air
```

其中 `first_contact_i` 只在某条腿由腾空转为接触的那个控制步为 1。

意义：

- 腾空少于 0.55 s 就落脚会产生负值；
- 腾空正好 0.55 s 时贡献为 0；
- 腾空超过 0.55 s 后落脚会产生正值；
- 非落脚瞬间该项为 0。

所以 0.55 s 严格来说是“正负分界阈值”，不是使奖励最大的目标点。该式会继续线性偏好更长腾空时间，理论上可能鼓励过大步幅或跳跃；跌倒、姿态、速度跟踪和接触惩罚负责抑制这种倾向。

它对崎岖地形的作用是减少贴地小碎步和过早落脚，使足端有更多时间跨越起伏。但它只在落脚事件上提供稀疏信号，且四腿求和不能保证每条腿都以合理频率参与。

### 4.2 `per_leg_swing`：四腿当前腾空时间的最小值

```text
t_min = min(t_FR, t_FL, t_RR, t_RL)
r_per_leg = m × clip(t_min, 0, 0.55)
R_per_leg = 3.0 × r_per_leg
```

设计意图是使用“最懒的一条腿”作为短板，防止只迈前腿、后腿拖地。原始值范围为 `[0, 0.55]`，单步加权贡献范围为 `[0, 1.65]`。

但 `t_i` 是“当前连续腾空时间”，任何正在接触地面的腿都有 `t_i = 0`。正常 walk 或 trot 步态通常至少有一条腿着地，所以 `min(t_i)` 几乎总为 0。只有四条腿同时离地时，该项才可能为正。这使它更接近“全身腾空奖励”，而不是“每条腿在一个步态周期内都迈过步”的奖励。

若要验证这个问题，可记录训练过程中 `R_per_leg > 0` 的步数比例，并与四足同时离地的步数比例对比；按当前公式二者应基本一致。

### 4.3 `gait_symmetry`：对角腿接触状态一致度

```text
match_1 = 1 - |c_FR - c_RL|
match_2 = 1 - |c_FL - c_RR|
r_sym = 0.5 × (match_1 + match_2) × m
R_sym = 0.2 × r_sym
```

原始值范围为 `[0, 1]`，单步加权贡献范围为 `[0, 0.2]`。它鼓励 `FR/RL` 和 `FL/RR` 两组对角腿各自保持相同接触状态，与 trot 的对角配对相符。

局限是该指标没有要求两组对角腿处于相反相位：

- 四足全部着地：两组都匹配，得到满分；
- 四足全部腾空：两组也都匹配，得到满分；
- 只有一组对角腿着地、另一组腾空：同样得到满分。

因此它衡量的是“对角组内一致”，不是完整的“交替对角步态”。较小的 0.2 权重说明它主要是弱引导项。

## 5. 崎岖高度场专项指标

### 5.1 `swing_foot_height`：摆动足相对高度接近 0.12 m

代码先用四只脚中的最低世界高度作为参考：

```text
h_i = foot_z_i - min_j(foot_z_j)
s_i = 1 - c_i
e = Σ_i [s_i × |h_i - 0.12|]
r_height = exp(-e) × I(-1.65 <= y <= 1.85) × m
R_height = 1.6 × r_height
```

设计意图是让未接触地面的摆动足相对支撑足抬高约 0.12 m，避免脚尖贴着崎岖表面运动而被高点绊倒。它是稠密奖励：处于崎岖区且存在移动命令时，每个控制步都会计算。

需要注意以下语义：

1. **它测量的是脚与“当前最低脚”的相对高度，不是真实离地间隙。** 若最低脚踩进凹坑，其余脚会显得更高；若支撑脚站在凸起上，也不能据此得到摆动足到前方地面的真实距离。
2. **没有摆动腿时会得到满分。** 四足都接触时 `s_i = 0`，于是 `e = 0`、`exp(-e) = 1`，单步贡献达到 1.6。这与“奖励抬腿”的字面含义相反。
3. **误差衰减较弱。** 误差直接以米为单位进入 `exp(-e)`，没有额外尺度。例如只有一只摆动脚且相对高度为 0 时，原始奖励仍为 `exp(-0.12) ≈ 0.887`，与理想高度的 1.0 差别不大。
4. **多只摆动腿的误差会相加。** 同样的单脚误差在两只脚同时摆动时会造成更强衰减，这会让不同接触相位下的奖励尺度不同。

因此，当前项主要提供“位于崎岖区就能获得的较强正向基线”，足高精度只对该基线做有限调制。它有可能让策略在崎岖区停留以持续取分；`anti_stall`、速度跟踪和进展项虽会对抗停滞，但是否足够需要从分项回报和分段通过时间判断。

## 6. 崎岖区出口落差指标

### 6.1 `drop_leg_catchup`：落差区的额外迈腿信号

```text
r_drop_leg = clip(min_i(t_i), 0, 0.55) × I(1.3 < y <= 1.8)
R_drop_leg = 4.0 × r_drop_leg
```

原始值范围为 `[0, 0.55]`，最大单步贡献为 2.2，是权重较大的区域专项项。设计意图是解决前腿先落到低处、后腿仍留在高处，导致机身前低后高而栽倒的问题。

然而公式与 `per_leg_swing` 使用完全相同的四腿最小当前腾空时间，只是增加了落差区域门控：

- 它没有只选择 `RR/RL` 两条后腿；
- 只要任意一条腿着地，该项就是 0；
- 正常的“前腿支撑、后腿依次跨过落差”过程通常得不到正值；
- 四足同时腾空反而获得正值。

所以它当前不能直接证明“后腿已经跟上”。更贴切的监控指标应是后足相对落差线的位置、后足越线事件、后腿离地事件，或一定时间窗口内两条后腿各自是否完成摆动。

### 6.2 `drop_pitch`：抑制落差区机身俯仰

```text
r_drop_pitch = g_x² × I(1.3 < y <= 1.8)
R_drop_pitch = -2.0 × r_drop_pitch
```

`g_x = 0` 对应机身 X 轴近似水平，绝对值越大表示俯仰偏离越大。该项没有非零目标，所以它实际鼓励机身在落差区保持水平，抑制前腿先下落造成的过度前倾，也抑制后仰。

在同一区域，全局 `orientation = -0.5 × (g_x² + g_y²)` 仍然生效。因此只考虑俯仰部分时，总惩罚约为 `-2.5 × g_x²`，落差区的水平姿态约束比普通路段强五倍。强约束有利于防止栽头，但也可能限制四足机器人在下台阶时自然调整机身姿态。

## 7. 上坡指标

### 7.1 `slope_leg_drive`：坡道驱动区的四腿最小腾空时间

```text
r_slope_leg = clip(min_i(t_i), 0, 0.55) × I(1.8 <= y < 6.9)
R_slope_leg = 3.0 × r_slope_leg
```

设计意图是让后腿持续蹬地、迈步，为爬坡提供推进力，并从 `y = 1.8` 开始接续落差区奖励。最大单步贡献为 1.65。

但该指标既没有测量足端推力、关节功率或向前地面反力，也没有单独选取后腿；它仍然是四腿当前腾空时间的最小值。因此“drive”在这里不是物理上的驱动力指标，而是一个足端腾空状态代理，并具有与 `per_leg_swing` 相同的“四足同时离地才非零”问题。

### 7.2 `slope_front_drive`：两条前腿的最小腾空时间

```text
t_front = min(t_FR, t_FL)
r_front = clip(t_front, 0, 0.55) × I(1.8 <= y < 6.9)
R_front = 3.0 × r_front
```

设计意图是防止只依赖后腿推、前腿不主动够向更高坡面。最大单步贡献同样为 1.65。

该式只有 `FR` 和 `FL` 同时腾空时才为正。正常 trot 中两条前腿通常处于相反相位，一条摆动时另一条支撑，所以该项大部分时间为 0；它衡量的不是“至少一条前腿正在积极迈步”，也不是“一段时间内两条前腿都完成了迈步”。

### 7.3 `slope_pitch`：坡面上的温和前倾目标

```text
r_slope_pitch = (g_x - 0.13)² × I(2.0 <= y < 6.9)
R_slope_pitch = -1.5 × r_slope_pitch
```

目标 `g_x = 0.13` 对应约 `arcsin(0.13) ≈ 7.5°` 的俯仰代理值。坡道约 15°，因此该奖励并不是要求机身完全贴合坡面，而是要求温和前倾，避免在坡道折角处因目标前倾过大而栽头。

全局 `orientation` 同时偏好 `g_x = 0`。忽略其他项，只合并俯仰相关的两个二次惩罚：

```text
L_pitch = 0.5 × g_x² + 1.5 × (g_x - 0.13)²
```

其最优点为 `g_x = 0.0975`，约对应 5.6°，而不是 7.5°。也就是说，实际奖励合力会把姿态拉向“比专项目标更平”的状态。这不一定错误，但解释训练姿态时不能只看 `slope_pitch` 的 0.13。

### 7.4 `slope_hip`：坡上髋关节偏离默认角的软阈值惩罚

对四个髋关节分别计算：

```text
d_i = |q_hip_i - q_default_i|
e_i = max(d_i - 0.2, 0)
r_hip = Σ_i e_i² × I(2.0 <= y < 6.9)
R_hip = -1.1 × r_hip
```

`0.2 rad ≈ 11.5°` 是不惩罚区间。该项允许髋关节在默认角附近正常摆动，只惩罚超出阈值的偏离，目的是防止坡上受力时前腿髋关节突然外张、支撑腿软倒。

实现上有两点需要准确理解：

- 使用 `abs()` 后，向外张和向内收超过阈值都会被惩罚，并非只惩罚外张方向；
- 对四个髋关节求和，并非只约束前腿。

这是一项安全性约束而不是前进动力。权重过弱时压不住塌腿，过强时则可能限制横向平衡和落脚点调整。

## 8. 指标之间的协同与冲突

### 8.1 设计上的协同链

理想情况下，这组奖励形成如下行为链：

```text
长一些的有效摆动
  -> 四腿都周期性参与
  -> 崎岖区提高足端间隙
  -> 落差处后腿及时跨过
  -> 坡上前后腿持续迈步
  -> 用温和前倾和髋关节约束保持稳定
```

速度跟踪、目标方向速度、前进进展和 `anti_stall` 则确保机器人不是只做步态动作，而是沿路径向前移动。

### 8.2 当前实现中的主要耦合问题

1. **接触态漏洞。** `swing_foot_height` 和 `gait_symmetry` 在四足全部着地时都能取最大值，而 `per_leg_swing` 类指标此时为 0。策略可能在“稳定站住拿两项正分”和“真正迈腿拿进展分”之间形成非预期折中。
2. **飞行态偏好。** 三个使用 `min(四腿腾空时间)` 的项会同时偏好四足离地。在落差或坡道区域，它们还会与通用 `per_leg_swing` 叠加，放大全身跳跃的激励。
3. **姿态目标叠加。** 落差区 `drop_pitch` 与全局 `orientation` 都偏好水平；坡道区 `slope_pitch` 偏好 0.13，而全局项偏好 0，实际目标由权重共同决定。
4. **区域边界突变。** 奖励通过 0/1 掩码突然启停，跨过边界的一个控制步就可能造成明显回报变化；这可能使策略学习到边界附近的速度或停留偏好。
5. **奖励没有乘控制周期。** 所有稠密奖励按 100 Hz 每步累加。因而单步 1.6 的 `swing_foot_height` 若持续 1 秒，累计量约为 160；不能直接拿它与一次性的 `reach_goal = 8` 只按权重数字比较。
6. **总奖励裁剪。** 所有分项相加后统一裁剪到 `[-100, 1000]`。极端惩罚若触发下限，会丢失不同失败严重程度之间的差异。

## 9. 建议监控的训练指标

为判断这些奖励是否真的提高崎岖地形通过率，不应只看总回报，建议按区域记录：

| 监控量 | 能回答的问题 |
| --- | --- |
| 各奖励项在各区域的均值、非零比例和累计贡献 | 哪些项真正提供了训练信号，是否有某项压倒其他项 |
| `per_leg_swing > 0` 与“四足同时腾空”的比例 | 验证最小腾空时间是否退化成跳跃指标 |
| 每条腿单位时间内的离地次数、落地次数、完整摆动周期 | 四条腿是否都在参与，而不是只看瞬时最小值 |
| 每条腿摆动期的真实地面净空分布 | 是否真的跨过地形高点，而非只相对最低脚抬高 |
| 后足跨越 `y = 1.5` 的时间差和失败率 | `drop_leg_catchup` 是否改善后腿跟进 |
| 坡道区前/后足切向地面反力、机身前进速度 | “drive”是否对应真实爬坡推进力 |
| `g_x` 在落差区、坡道区的分布 | 姿态奖励是否得到预期的水平或温和前倾 |
| 各髋关节超过 0.2 rad 的比例 | `slope_hip` 是否过弱或过强 |
| 各路段进入率、通过率、耗时和失败类型 | 奖励提升的是局部分数还是真实任务成功率 |

代码已经把各分项的加权贡献写入 `info["Reward"]`，也记录了 `rough_mask`、`terrain_scan_*` 等基础指标；但上述足端事件和分路段成功率仍需补充记录，才能完整验证奖励含义。

## 10. 若要使公式更贴近名称，建议的改进方向

以下是指标定义层面的方向，不代表必须同时修改全部权重。

1. `swing_foot_height` 应显式要求至少存在一条摆动腿，并按摆动腿数量归一化；最好使用足端相对其下方地形的真实净空，而不是相对最低脚高度。
2. `per_leg_swing` 应使用滑动时间窗内“每条腿是否完成过摆动/落地事件”的最小完成度，而不是同一时刻四腿腾空时间的最小值。
3. `drop_leg_catchup` 应直接选择 `RR/RL`，结合后足跨越落差线、后足摆动事件或前后足越线时间差。
4. `slope_leg_drive` 若要表达“驱动”，可依据后腿沿坡向的地面反力、正机械功率或落脚后的机身前进增量；若只想鼓励迈步，应改名以免误解。
5. `slope_front_drive` 可奖励两条前腿在时间窗内轮流完成摆动，而不是要求它们同时腾空。
6. `gait_symmetry` 除对角组内一致外，还应加入两组对角腿反相或相位差约束，并在全足着地/全足腾空时避免给满分。
7. 区域门控可在边界附近采用连续权重过渡，减少奖励突变。
8. 同步更新 `8factors.md` 与配置值，或让文档从配置自动生成，避免训练参数与说明继续漂移。

## 11. 总结

这组奖励覆盖了复杂地形通过所需的三个核心能力：足端净空、跨越衔接和坡上稳定。`swing_foot_height`、`drop_leg_catchup`、`slope_leg_drive/front_drive` 提供区域专项动作塑形，`drop_pitch`、`slope_pitch`、`slope_hip` 提供姿态和支撑约束，通用的 `feet_air_time` 与 `gait_symmetry` 提供步态先验。

不过，指标名称表达的是设计目标，公式表达的才是策略真正优化的目标。当前最需要谨慎解读的是“当前腾空时间最小值”和“无摆动腿时抬腿奖励满分”这两类问题。训练评估时应以分项非零比例、逐腿事件、真实足端净空和分路段通过率为依据，不能仅凭总奖励上升判断崎岖地形能力已经改善。
