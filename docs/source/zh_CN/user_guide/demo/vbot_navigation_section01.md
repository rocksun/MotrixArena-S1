# `vbot_navigation_section01` 运行适配工作说明

## 背景与目标

为了让 VBot 能够在 Section01 场景中完成强化学习训练与策略验证，本次工作围绕“场景可加载、环境可发现、任务可训练、结果可回放”四个目标，对 MotrixLab 的环境层和训练层进行了完整接入。

Section01 不是单一平面行走任务，而是一条包含崎岖路面、落差和坡道的连续路线。因此，适配工作的重点不仅是把场景加载起来，还包括建立路径导航逻辑、补充地形信息、处理接触状态，并让奖励设计能够覆盖不同路段的运动需求。

## 完成的工作

本次工作涉及的主要文件如下：

| 文件 | 作用 |
| --- | --- |
| `motrix_envs/src/motrix_envs/__init__.py` | 将导航模块加入环境包的启动导入链路。 |
| `motrix_envs/src/motrix_envs/navigation/__init__.py` | 导入并公开 Section01 环境及其配置，触发注册装饰器。 |
| `motrix_envs/src/motrix_envs/navigation/cfg.py` | 定义场景、初始状态、路径、控制、奖励、碰撞体和传感器配置。 |
| `motrix_envs/src/motrix_envs/navigation/vbot_section01_np.py` | 实现 NumPy 后端下的动作、观测、导航、奖励、终止和重置逻辑。 |
| `motrix_envs/src/motrix_envs/navigation/xmls/` | 保存 VBot、Section01 场景、碰撞模型和网格资源。 |
| `motrix_rl/src/motrix_rl/cfgs.py` | 注册与该环境同名的 PPO 训练配置。 |
| `.gitignore`、`uv.lock` | 管理大型场景资源的提交边界，并同步项目依赖状态。 |

### 1. 接入 Section01 场景资源

- 在 `navigation/xmls` 中整理了 VBot 模型、Section01 场景描述以及关联的网格和碰撞资源，并由 `VBotSection01EnvCfg` 加载 Section01 专用场景。
- 场景中区分了视觉模型和用于物理计算的碰撞模型。环境根据 Section01 的真实碰撞轮廓识别崎岖区、出口落差、坡道和终点平台，而不是只按视觉外观推测地形。
- 对足端建立分组接触传感器，用于判断每条腿是否着地、计算腾空时间并获取接触力；对机身关键部位建立接触检测，用于识别跌倒；其余腿部和机身碰撞则作为非期望接触处理。
- 将 `navigation/xmls` 加入忽略规则，避免大量场景网格直接进入普通代码提交。相应代价是运行机器需要单独准备完整资源目录。

### 2. 完成环境注册与加载链路

- 在 `motrix_envs/__init__.py` 中启用 `navigation` 包，使导入 `motrix_envs` 时能够自动执行导航任务注册。
- 在 `navigation/__init__.py` 中显式导入 `vbot_section01_np` 和 `VBotSection01EnvCfg`，确保环境实现与环境配置都进入注册表。
- 环境实现通过 `vbot_navigation_section01` 与 NumPy 后端绑定；环境配置和强化学习配置也使用同一个名称。通用脚本收到 `--env vbot_navigation_section01` 后，可以依次找到场景配置、环境类和 PPO 配置。
- 清除了尚未使用的其他 Section 变体，并暂不加载无关的 locomotion 环境，减少启动阶段因缺失资源或重复配置导致的注册问题。

完成后，通用的查看、训练和回放脚本都可以通过任务名称找到该环境，无需为 Section01 维护独立入口。

### 3. 实现 Section01 导航环境

`vbot_section01_np.py` 新增了基于 `NpEnv` 的 `VBotSection01Env`。每个仿真步的处理顺序为：读取接触状态、更新路径指令、判断终止、计算奖励、生成下一帧观测。主要实现包括：

- **动作执行**：将策略输出裁剪后映射为相对默认站姿的关节目标，再通过位置控制计算各关节执行力，并按执行器能力限制最终输出。
- **基础观测**：读取机身局部速度、角速度、重力方向、关节位置偏差、关节速度、上一帧动作和当前导航指令。
- **地形与接触观测**：汇总四足接触力，并根据机器人前方的 Section01 地形剖面生成地形扫描信息，让策略能够在到达落差或坡道前获得提示。
- **状态安全处理**：对观测和控制数据中的非有限值进行兜底处理，避免异常数值继续传播到训练器。
- **重置逻辑**：恢复默认站姿和速度，在起点区域内随机初始化位置、朝向与关节状态，同时重置路径进度、动作历史、足端腾空时间和统计数据。
- **终止逻辑**：在机身关键碰撞体触地、仿真状态异常或完成全部路径点时结束回合；时间上限则交给框架按截断处理，便于训练器正确进行时间限制回报计算。
- **训练指标**：记录当前路径点、目标距离、路径推进、实际速度、地形状态、异常接触和任务成功率，便于在日志中判断策略卡在哪个路段。

这些内容构成了强化学习算法与仿真场景之间的完整交互闭环。

### 4. 建立分段路径导航逻辑

Section01 采用沿路线逐步推进的路径点导航方式，而不是直接追踪单一终点。路径点从起步区开始，依次覆盖崎岖区出口、落差衔接、坡道中段、坡顶和终点平台。

环境在每一步取得当前目标与机器人之间的世界坐标差值，再根据机身朝向转换到机器人局部坐标系，分别生成前进、横移和转向指令。到达当前路径点后立即切换到下一点，全部路径点完成后将任务标记为成功。

针对连续地形切换，还加入了以下处理：

- 对原始导航指令进行一阶平滑，减少目标点切换时速度和转向突然变化；
- 对普通路面、崎岖区、落差衔接区和坡道分别限制运动节奏，避免策略以平地速度直接冲击复杂地形；
- 在接近坡道折角时提前减速，降低惯性导致的前栽风险；
- 地形扫描使用机器人前方的一组采样点描述即将到来的地面变化，并随机器人位置实时更新；
- 路径点进度、当前目标和距离均保存在环境状态中，可由并行环境分别推进，不会互相干扰。

### 5. 完善奖励与稳定性约束

奖励设计围绕“沿路线前进并稳定通过复杂地形”展开，主要覆盖：

- 速度、朝向和目标方向的跟踪；
- 路径推进、路径点到达和整段路线完成；
- 四足主动迈步、步态协调与足端抬升；
- 崎岖路面、落差和坡道路段的专项运动需求；
- 跌倒、异常接触、失速、姿态不稳和控制突变等失败行为。

在基础导航奖励之上，针对实际训练中出现的失败模式进行了专项处理：

| 训练现象 | 对应处理 |
| --- | --- |
| 只依靠前腿移动，后腿长期拖行 | 按四条腿中最不活跃的一条计算迈步奖励，要求每条腿都参与摆动。 |
| 崎岖区采用贴地小碎步，足端容易被凸起绊住 | 在崎岖区单独鼓励摆动腿形成足够离地间隙。 |
| 前腿先越过出口落差，后腿停留在高处导致身体前栽 | 在落差衔接段强化后腿跟进，并约束机身俯仰变化。 |
| 到达坡道后动力不足或只有部分腿发力 | 在坡道范围内同时要求前后腿持续迈步和蹬地。 |
| 冲上坡道折角时机身过度前倾 | 将坡道减速与坡上姿态约束结合，避免以平地步态直接冲坡。 |
| 上坡受力时髋关节外张、前腿失去支撑 | 对坡道区域内过度髋关节偏移增加约束，使腿保持在稳定支撑范围。 |

奖励计算同时保留各子项的独立贡献，写入环境的 `Reward` 信息。这样可以区分总奖励增长究竟来自路线推进、步态改善，还是某一项惩罚减弱，便于后续继续调试。

### 6. 接入强化学习训练配置

- 在 `motrix_rl/src/motrix_rl/cfgs.py` 中新增 `VBotNavigationSection01PPOConfig`，并使用环境名称完成注册。
- 配置中覆盖了训练和回放时的并行环境规模、训练总量、采样与更新流程、策略及价值网络、检查点保存等 PPO 必需内容，因此不需要修改通用训练脚本。
- 保留时间限制回报处理，使达到回合上限和真正跌倒在训练语义上得到区分。
- 清理了暂未使用的 Section02、Section03 配置，避免当前阶段出现名称相近但场景不完整的任务入口。
- 更新 `uv.lock`，同步当前工作环境解析出的依赖版本和锁文件格式。

## 运行链路

以训练命令为例，代码执行关系如下：

```text
scripts/train.py
    -> 根据任务名查询 motrix_rl 配置注册表
    -> 根据任务名和后端查询 motrix_envs 环境注册表
    -> VBotSection01EnvCfg 加载 scene_section01.xml
    -> VBotSection01Env 创建并行仿真环境
    -> PPO 与环境循环交互并保存日志、指标和策略检查点
```

查看和回放脚本复用同一套环境注册与场景配置，区别仅在于不执行 PPO 参数更新；回放时还会从指定策略文件恢复模型。

## 运行方式

在项目根目录下，可使用统一脚本完成环境检查、训练和策略回放：

```bash
# 查看环境是否能够正确加载
uv run scripts/view.py --env vbot_navigation_section01

# 启动训练
uv run scripts/train.py --env vbot_navigation_section01

# 回放训练结果
uv run scripts/play.py --env vbot_navigation_section01 --policy <策略文件路径>
```

如需观察训练过程，可使用项目已有的 TensorBoard 流程读取该任务的运行日志。

## 运行前提与注意事项

- 必须保证 `navigation/xmls` 下的 Section01 场景、VBot 模型及其关联资源完整存在。该目录当前被 Git 忽略，不会随普通代码提交自动分发，需要单独准备。
- 环境注册名、环境配置注册名和训练配置注册名必须保持一致，否则通用脚本无法正确组合仿真环境与训练配置。
- 当前任务实现使用 NumPy 仿真后端；切换后端前需要确认对应环境实现已经注册。
- 场景或机器人模型中的几何体、关节和传感器名称若发生变化，需要同步检查环境中的索引和接触检测逻辑。
